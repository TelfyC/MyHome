# Plan C 架构与图纸转录说明

## 数据与制品

```text
home1.png + 显式估算／设计假设
  → planC/data/sunlit/scene.json
  → Schema + 几何 + 资产门禁
  → 固定 Blender Worker
  → project.blend + scene.glb + 对象映射 + build_manifest
  → 同版相机的 Cycles 静态／球形全景
  → 文件、尺寸、SHA256、版本和相机 QA
  → public/plan-c/ → 当前网站 ?view=plan-c
```

运行时无生图 API 依赖。网页原四风格继续读取原资源，Plan C 只读取独立的 `plan-c/` 资源清单。

| 位置 | 职责 |
| --- | --- |
| `planC/archviz/models.py` | Pydantic 类型与跨对象引用 |
| `planC/archviz/store.py` | SQLite 事务、不可变版本、乐观锁、Patch 审计 |
| `planC/archviz/constraints.py` | 房间自交、墙重叠、洞口、OBB家具与支撑检查 |
| `planC/archviz/assets.py` | 本地资产路径／哈希／许可／专业资产门禁 |
| `planC/archviz/jobs.py` | 固定命令任务、状态与失败重试 |
| `planC/archviz/qa.py` | 实际 Blender／图像制品与版本验证 |
| `planC/blender/build_scene.py` | 建筑、门窗、细节家具、材质、灯光和相机 |
| `planC/blender/import_assets.py` | 已登记本地专业模型导入；不做网络爬取 |
| `planC/blender/render_scene.py` | Cycles 固定分辨率／采样配置与逐图记录 |
| `planC/scripts/export_site.py` | 只发布匹配 Scene／Build 的实际制品 |
| `src/plan-c.ts`、`src/plan-c.css` | 独立网页体验与同场景 GLB 查看 |

## home1.png 的处理

原图明确写着“其余尺寸按邻近区域比例估算，纵向亦为推算值”“分区估算示意，非统一比例施工图”。因此不能把全图用一个像素比例标定，也不能把转录数据标成实测。

本版保留：左下主卧、主卧上侧原卫浴区、左上卧室、中下卧室、右侧起居室、上侧餐厅与阳台、右上厨房、右侧入户和起居室下端收窄轮廓。原白墙保留；墙体颜色不等于承重性质，全部保持 `structural_state: unknown`。

主要参考宽度：主卧约3.25m、中下卧室约2.75m、起居室主段约3.30m、餐厅约2.50m、右上厨房约2.15m、左上卧室约3.20m。墙线以中心线表示，墙厚黑色段暂取0.20m、白色段暂取0.12m。除来源图的标注外，墙厚、层高2.70m、洞口高度、窗台和部分位置均是设计推断。

坐标采用右手系，米／弧度，+Z向上、+Y对应图纸上方。`coordinate_system.north` 表示项目坐标轴约定，`site.true_north_offset_rad: null` 明确真实地理北向未确认，不把图纸方向当作日照事实。

起居室下侧和卧室阳台下侧玻璃由图线推断，置信度较低，单列待确认项。卫浴区下侧未画清建筑隔断，首版没有擅自增加隔墙；卫浴隐私、排水及使用动线仍需进一步设计。

生成器 `planC/scripts/create_demo.py` 保留每个对象的稳定ID和来源。没有进行OCR识别或宣称自动完成图纸解析；当前是可审查的人工数字化首版。`uncertainties.json` 与网页报告保留全部疑点。

## 实际建模与材质

墙洞由宿主墙的沿墙偏移、宽度、窗台和高度生成，墙段在洞口位置实际分割。门洞保留开放状态以观察相邻空间。地面和天花向墙下延伸0.11m，再用共享XY网格把每个饰面单元只分配给一个房间，避免共面交叠造成黑带；数据中的房间净轮廓保持原样。当前饰面构建支持本图的正交房间，斜边房间会明确拒绝，不会被拉直替代。

自建模型包含圆角与拼缝柜体、软包沙发和缝线、靠垫、木腿餐椅、床品、书籍、植物叶片、厨卫器具等。模型在清单中明确为 `custom_fixture`／开发预览资产，未冒充已审核商业高模。

原木、织物和墙面采用程序材质；无外部贴图下载和不明授权资源。玻璃使用实际透射材质。GLB只作为几何和摆位查看，程序节点不会完整转为glTF材质，因此材质效果以Cycles图像为准。

Scene 中的基色按sRGB转换到线性空间，粗糙度、金属度和纹理尺度实际写入着色器。对象的 `material_id` 绑定主表面，保留木腿、金属、玻璃、叶片和屏幕等细节。真实Blender测试以两套颜色和粗糙度重建沙发，并重新打开工程确认材质变化及木腿保留；证据在 `planC/data/material-verification.json`。

## 状态与门禁

预览允许带来源警告的估算场景，在Schema、引用、开口、布局和资产许可检查后构建。正式任务还要求尺寸校准、专业Hero资产审核与完整视觉验收。未知墙拆改、资产缺失或许可错误均不能自动放行。

静态图与全景均记录 `scene_revision`、原始Scene文件哈希、`build_id`、`camera_id`、profile、真实像素、渲染器版本和图像SHA256。构建还记录执行器／资产导入器哈希。失败不回退到旧图伪装成功；最多三次有记录的不同修复尝试。

九个角色提示词已保留，但没有把提示词文件存在等同于九个LLM在线运行。当前可执行部分是状态机、Scene服务、白名单Worker和QA。后续可在不更换事实源的前提下接入Design／Asset／QA模型调用层。
