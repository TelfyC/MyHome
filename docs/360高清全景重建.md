# 360° 高清全景重建

本轮沿用四套风格、七个房间已经确认的图片设计，以原全景作为编辑参考，通过图片 API 生成更高分辨率的素材，再单独修复经度接缝。尺寸模型没有代替现有全景重新设计房间。

当前状态：28 张 3840 × 1920 高清母版已生成；接缝处理、逐图目视复核和浏览器验收仍在进行。本文先记录方法、路径和重建方式，不据此宣称所有图片已经通过最终验收。最终汇总记录位置为 `home-design-review/input/panorama-native-20261028.json`，验收截图位置为 `artifacts/panorama-native-20261028/`，以最终记录状态为准。

本轮通过 `gpt-image-2` 图片编辑接口明确设置 `size=3840x1920`、`quality=high`、`n=1` 和 PNG，实际检查返回文件尺寸。单纯把尺寸写进提示词不作为输出参数生效的证据。返回尺寸也不能独立证明提供商内部的渲染方法，或断言所有新细节都准确忠实于源图。

## 高清生成

`scripts/build-native-panoramas.py` 调用已安装的 imagegen 技能 CLI，不另外实现一套 SDK 生图服务。每张图对应一个输入全景、一份提示词和一个返回 PNG；分别记录源图、输出图的尺寸和 SHA256、请求参数、耗时以及错误状态。

提示词要求保留机位、经度朝向、完整球面覆盖、原有门窗、家具、通路、玻璃门、窗帘、配色和光照，只细化木纹、五金、织物与表面质感。普通布面保持素面，不凭“提高细节”新增浮雕和装饰图案。已有林中树屋客厅测试结果仅在源图哈希、模型、接口地址、尺寸和输出哈希都匹配时复用，避免无意义的重复调用。

API 生成不是几何约束的精确求解。局部植物叶形、织物纹样、家具细节及小物件仍可能漂移，应逐图对照。图中门窗与家具不能用来反推施工尺寸，尺寸仍以模型与现场复测为准。

## 经度接缝修复与局部合成

图片的左右边缘代表空间中相邻的方向，原图已有的内容错位不会因分辨率提高而自动消失。`scripts/finish-native-panoramas.py` 分开保存以下处理阶段：

1. 把 3840 像素宽的高清母版横向循环旋转 1920 像素，使原经度接缝位于图片中央，原图朝向在处理后会恢复。
2. 创建完整尺寸 RGBA 蒙版，仅让中央经度条带透明；其余区域为保留上下文。条带覆盖全高，提示词要求继续保留天花和地面的球面投影。
3. 以旋转后的图片和蒙版调用同一图片编辑接口。要求在中央修复墙、窗框、窗帘、植物及地板的连续性，保留完整物体与原有窗台高度，避免把窗改成门、扩大玻璃或新增物件。
4. 初版用固定条带与余弦羽化合成，目视检查发现窗框和家具轮廓错位会形成重影，因此只保留为候选。最终由 `scripts/publish-native-panoramas.py` 在原高清图与接缝返回图之间寻找两条像素差异较小的连续路径：每行允许左右移动一个像素，综合颜色差、梯度差与边缘强度求解。路径之间采用修复图，外侧采用原高清图，交界只做总宽 3 像素的过渡。
5. 检查路径是否截断窗框、灯具或家具。默认左右各在距离图像中心宽度的 12%–25% 内寻找路径；可分别收窄两侧范围，实际参数记录在逐图汇总。蒙版属于生成指导，API 仍可能改变其外部内容，最终合成保留范围以路径为准，不能把它等同于蒙版范围。
6. 反向旋转恢复原朝向，保存合成 PNG，并导出 JPEG 网页文件。合成母版在两条路径外与原高清输入逐像素一致，首尾像素来自修复图中相邻的中央像素。JPEG 使用 quality 94、无色度抽样和渐进编码；JPEG 压缩本身会改变像素，不能把网页文件称为原始 API 输出或逐像素保留的母版。

脚本默认编辑条带约占经度宽度的 30%，完全替换核心约占 26%，实际宽度按 32 像素对齐。范围应结合画面中的完整窗、台灯、凳子和植物选取；调整参数需要使用新的归档目录，不能把不同修复配置混在同一断点记录里。`--preserve-note` 可补充特定图片的物体与几何保留要求，内容会写入提示词记录。

局部复合用于限制 API 漂移；最小误差路径也不能判断物体语义，仍需检查两侧接合位置是否有截断、重复或几何变化。接缝两侧 RGB 差异仅作为描述性指标；数值下降不等于物体、几何和视觉效果已经验收通过。`scripts/compose-panorama-seams.py` 可单独生成投影对照与路径预览，不修改网页素材。

API 返回 PNG、旋转输入、蒙版和合成母版只在本地归档，Vite 不会把 `output/`、`artifacts/` 自动复制到网站。网站运行时只读取 `public/` 的导出素材，不调用生图接口，也不携带密钥。旧 `public/panoramas-hd/` 和 [360 高清增强](360高清增强.md) 是此前 Real-ESRGAN 4 倍超分方案的历史记录，当前高清入口使用新目录。

## 接口和本地配置

当前使用用户指定的兼容地址 `https://api.oaipro.com/v1`，调用令牌由用户自行配置在项目外的 `~/.config/home3d/openai-api-key`，文件只含密钥本身。密钥不写进提示词、结果汇总、网页源码或日志；调用子进程仅设置本次 API 地址与密钥，不修改 Codex 配置、shell 配置或现有代理。

本地需要 Python、Pillow、NumPy 和 OpenAI Python SDK，并可找到已安装 imagegen 技能的 `scripts/image_gen.py`。本次环境的 SDK 安装在 `/tmp/home3D-native-panorama-deps`，编排脚本会自动加入该依赖路径；临时目录清理后需要重新安装。脚本支持 `--cli` 指定实际技能 CLI 路径，支持 `--base-url`、`--key-file` 指定对应的服务与本地令牌文件。

## 重建与断点继续

以下命令从项目根目录运行。先看生成计划；此步骤不读取密钥、不写输出、不调用 API：

```bash
python3 scripts/build-native-panoramas.py --dry-run --workers 2
```

生成或核验已存在的高清母版后继续；已有输出只有在来源、参数、尺寸和哈希匹配时才会复用，不隐式覆盖：

```bash
python3 scripts/build-native-panoramas.py --workers 2 --skip-existing
```

按脚本默认参数准备单间修复输入、蒙版和参数预览。该 dry-run 会写本地准备文件，但不读取密钥或发送 API 请求：

```bash
python3 scripts/finish-native-panoramas.py \
  --artifacts output/imagegen/panoramas-native-20261028/seam-repair-wide \
  --styles forest --rooms living --dry-run
```

执行全部接缝修复，或按同一目录与参数断点继续。已有完整结果会校验文件与哈希后复用：

```bash
python3 scripts/finish-native-panoramas.py \
  --artifacts output/imagegen/panoramas-native-20261028/seam-repair-wide \
  --workers 2
```

使用已保存的输入与 API 返回图进行路径合成和网页导出。此步骤不读取密钥、不调用 API，可以反复检查、调参和导出：

```bash
python3 scripts/publish-native-panoramas.py --workers 2
```

单间调参使用相同的 `--styles`、`--rooms` 选项，并通过 `--left-outer-fraction`、`--left-inner-fraction` 等控制两侧搜索范围。部分重新导出会扫描所有已存在的逐图记录，保留完整汇总。原始 API 输出和初版候选继续保留。

可以用 `--styles`、`--rooms` 限定一组图；修复目录、条带宽度或保留要求以实际逐图记录为准。改变配置时另设 `--artifacts` 目录，旧记录与原始输出继续保留。

生成脚本和修复脚本均不会在一次外层执行中自动重复一个失败的生图任务。对于失败或超时且结果不确定的记录，应先检查脱敏日志和服务端任务状态；确认需要新请求后，再显式使用 `--retry-failed`。技能 CLI 内部 SDK 对短暂传输问题仍可能有默认重试，这一点记录在结果中。

## 页面加载与验收

`src/panorama-hd-data.ts` 为每张桌面与手机版本记录路径、宽高；`src/panorama.ts` 按视口和 GPU 最大纹理尺寸选择可用资源，并核对加载文件的实际尺寸与 2:1 比例。手机优先 2560，桌面优先 3840；连 2560 宽资源都不支持时保留原图。资源加载失败或与记录尺寸不符也保留原图，且升级不得重置朝向、俯仰、缩放、自动旋转或正在查看的功能区。

`?design=forest&room=living&quality=original` 只加载正文原图；新版缩略图仍用于房间导航。默认链接与该原图链接可在相同朝向和显示尺寸下对照。对比截图属于重采样后的展示视图，不是 API 原始尺寸的证据。

验收应分别检查返回尺寸和哈希、材质细节、主要家具和门窗、球面投影、首尾接缝及修复条带两侧的轮廓连续性，再进行浏览器验证：

```bash
npm run build
npm run dev
# 另开终端，在开发服务可访问时运行：
npm run test:panorama
npm run test:quality
node tests/spatial-updates.mjs
```

`test:panorama` 检查全部原图和 84 个新版网页文件的尺寸、房间与风格切换等；`test:quality` 检查桌面/手机选图、渐进加载、设备纹理上限、失败回退与异步竞态；`spatial-updates` 检查高清替换后功能区与交互状态仍保持。最终通过情况由验收截图和汇总记录补充，本方法说明不代替逐图验收。
