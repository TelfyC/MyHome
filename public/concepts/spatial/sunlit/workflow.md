# 日光花园：先锁房型，再出效果图

本轮把11月2日风格方案放回同一套建筑边界。图纸、家具和机位共用结构底稿；效果图在底稿之上表现材质、光照和装饰。自动几何检查与生成图的目视检查分别记录。

## 1. 先确定各类资料能证明什么

- 最新用户确认和专项布局决定房间用途、删窗、家具方向、厨房L台与收门方式。
- `newStructure.jpg`只转录手写尺寸，不恢复图中的旧卫浴、储物间、侧窗或隔墙。该图有拍摄透视，缺失尺寸不按像素补齐。
- `dimensions.ts`提供统一尺寸链；`model.ts`的实际墙线提供已接受的门窗、转角位置。导航矩形不能直接当作建筑轮廓，尤其主卧入口必须保留凹角。
- 最新设计图提供日光花园的木色、暖白、条纹、陶器、绿植与咖啡插排细节，不提供可量取的建筑尺寸。
- 旧Plan C由旧图转录，卫浴、窗和厨房尺寸与后续确认不一致；本轮不直接把它作为事实源。

来源、优先级、SHA256及每项“已接受设计／模型假设／拟定尺寸”见[约束清单](constraints.json)。照片中的墙色不等同承重鉴定，图纸上方也不代表已确认地理北向。

## 2. 建立一份结构场景

全屋保持20个外轮廓顶点。特别锁定玄关外凸、客厅东侧回折、南端收窄、上阳台外凸和主卧入口内退。房间、墙、9处窗、5处室内/入户门、厨房玻璃围合、家具和相机都记录在同一份[导出场景](references/scene.json)里。

外轮廓、共享墙和开口只建一次，多个房间观察同一个对象；不为每张图片重新编一遍门窗。沿墙的尺寸采用同一坐标，家具保持实际拟定尺度，位置调整不靠缩放房屋完成。

厨房在旧模型基础上落实北洗炒、东北冰箱、东短台与南备餐台的L关系。南台后固定界面和清玻璃与剩余四扇向左叠收配合；西侧五扇沿原方向收纳。柜体共享转角不重复计算可用空间。客厅用阅读椅、脚凳和小边几替代旧大植物角。

当前统一坐标中，北台前沿`z=.74`、南台前沿`z=2.00`，静态净距为1.26m；南门组静态净开口为1.39m。10月28日文字方案的1.29m与1.25–1.30m是按约3.10m围合及约数推算，不能冒充与现有坐标完全相同的实测值。检查报告保留差异。餐厅南端椅与公共区处于连续开放空间，其后缘跨越功能分区约0.10m会被明确登记；这不代表有人就坐或拉椅时仍拥有相同通路。

## 3. 用代码检查结构与摆位

在项目根目录运行：

```bash
python3 scripts/check-sunlit-spatial.py
```

默认读取`references/scene.json`与`constraints.json`，写出[几何检查报告](geometry-check.json)。报告记录实际场景SHA256、逐项结果和失败原因；缺场景或不通过会返回非零退出状态，不能把旧图当新图放行。

检查包括：20顶点及坐标、正交外形、房间标识、两面连续共享实墙、9窗位置与窗台高度、5门位置、主卧入口退台、全部声明家具在本房内且不穿墙/门槛、不同家具实体相交、核心家具左右/前后顺序、相机位置及眼高。台面与转角柜、设备与其支撑柜需明确登记共享关系，不能无条件忽略重叠。

几何检查只核验确定性场景与声明的家具外包轮廓。家具子件、门扇/抽屉动态扫掠、人体使用范围、设备安装间距还需按选型深化；它不是对施工适用性的认证。

## 4. 每个机位先输出结构底图

从同场景生成各房间俯视位置图与固定相机透视。俯视用于看凹角、门窗、家具占位；透视用于看该机位实际能看见的墙面、窗和相邻空间。近景直接裁取或从同一相机体系另设机位，不独立重造咖啡柜、插排或窗边。

相机位置、方向、视角和图像尺寸随文件存档。设计图可以不展示所有折角，但不能把未入画的转角当作已核对。

相机是软件机位：例如客厅主机位的平面投影位于沙发范围内，眼高超过靠背，实际视线不穿实体；这里没有模拟摄影者或脚架的站立空间。家具静态净距与相机视线分别核验，不据此声称能够按同样位置实地拍摄。

## 5. 以结构底图约束内置生图

每次输入明确区分“结构与机位参考”和“风格参考”：结构图决定轮廓、墙洞、家具位置及透视；11月2日图只决定材质、深浅木、织物与小物。提示词逐项锁定本房实际可见的开口、墙角、家具方向；不要求AI凭文字猜一间更漂亮的房子。

设计图片保留独立版本，完整提示词、参考文件、生成源和选择结果可追溯。修改结构后必须从该场景重新输出底图，不能仅靠修饰词掩盖结构变化。

## 6. 逐图目视复核并明确状态

将生成图与同机位结构参考并排查看，按以下次序检查：

1. 房型是否镜像、伸长，所有入画转角是否仍在。
2. 窗/门是否位于同一面墙，数量、相对位置及高低窗关系是否变化。
3. 沙发电视、床桌、咖啡柜、冰箱与台面等的方向和相对位置是否一致。
4. 门口、收门区、过道是否被AI新增家具、柜体或绿植占用。
5. 全景与近景是否保留同一窗、同一机型、同一插排位置和柜体比例。

结果单独写入[视觉复核记录](visual-review.json)，注明审查者、参考图、逐图发现和“通过／有偏差／未检查”。发现硬结构错误的图片不标为通过；允许再次修正或以确定性结构渲染展示准确摆位。

**自动几何通过不等于AI图片几何通过。** 生成照片无法仅凭scene.json证明像素中的尺寸完全正确。当前资料也不足以保证与实测墙体完全一致，页面需保留这一具体边界。结构底图提供可审查的一致几何，风格图提供经目视筛选的效果。

## 7. 发布前核对实际制品

校验每张最终图可解码、尺寸符合记录、SHA256唯一且引用存在；页面逐房切换能同时到达结构俯视与效果图。保留旧版，新增版本入口与来源说明。修改结构、家具或相机后重新运行检查，旧报告的SHA256不得继续套用。

当前资料中没有独立实测的门窗宽高、层高、完整墙厚和部分错位尺寸。相关值是模型假设，在拿到复测值后只需更新统一结构源，再重新出图与核验。
